# AVTool

个人视频目录、筛选、播放与云盘缓存工具。默认普通模式支持用户自行提供的 Bilibili、抖音链接。**仓库不包含成人站点、成人爬虫、视频片库、账号或云盘授权；特殊模式是需要自行配置适配器的扩展入口。**

## 1. 手动部署

Git 仓库仅提供源码，不上传网页构建产物。首次启动会安装依赖并在你的本机构建网页，需要联网。

### Windows

1. 安装 Python 3.10+（推荐 3.12）和 Node.js 22.12+（推荐 24 LTS），确保 `python` 或 `py`、`node`、`npm` 可以在终端运行。
2. 从本仓库页面选择 **Code → Download ZIP**，完整解压到自己的目录；也可以使用 Code 按钮提供的地址克隆仓库。
3. 双击 `start-windows.bat`。脚本会创建项目虚拟环境、安装 Python 和前端依赖、构建网页并启动服务。
4. 打开 `http://127.0.0.1:8787`。停止时在终端按 Ctrl+C。

需要分离音视频或 HLS 播放时，安装 FFmpeg（包含 `ffprobe`）并加入 PATH；需要云盘缓存时，还需安装 rclone 并配置自己的独立授权。

### Ubuntu

先安装 Node.js 22.12+（推荐 24 LTS），确认 `node --version` 与 `npm --version` 正常。然后安装其他依赖：

```bash
sudo apt update
sudo apt install python3 python3-venv ffmpeg rclone
```

从仓库下载或克隆源码，进入包含 `start-ubuntu.sh` 的目录，执行：

```bash
bash start-ubuntu.sh
```

打开 `http://127.0.0.1:8787`；Ctrl+C 停止。不安装开机启动服务，不需要挂载云盘。

### 第一次使用

点击网页的“导入链接”，粘贴自己有权使用的 Bilibili 或抖音链接。导入仅保存目录信息；可先尝试源站播放，再手动缓存到自己的云盘。

首次启动生成本机 `config.json`。云盘默认关闭；启用步骤见 [安装与使用](DEPLOYMENT.md)。`config.json`、`.secrets/`、`private/`、运行数据和本机构建的 `web/out/` 均被 Git 排除，不要上传。

## 2. 用 AI agent 自动部署普通模式

把本仓库链接和下面这段话交给你的 agent：

> 请将这个仓库部署到我指定的本机目录。先阅读 README.md、AGENT_DEPLOYMENT.md、DEPLOYMENT.md 和使用政策，检查 Python、Node.js 版本，按我的系统运行 Windows 或 Ubuntu 启动脚本并完成本机构建。保持 mode=ordinary、来源为空、云盘关闭；只监听 127.0.0.1，不设置公网端口、反向代理或公开隧道，不覆盖既有实例，不导入任何他人的数据和凭据。验证首页、导入页及空目录可用，告诉我本机访问地址、启动和停止方法。需要我提供账号授权或合法测试链接时再向我索取必要信息，不要索取公开粘贴的密钥。

普通模式不用 Google 或 Drive 授权即可启动。需要云缓存时，agent 应引导你配置自己的独立 rclone 文件，不能复用作者或系统中其他人的登录状态。

## 3. 特殊模式：部署后手动增加站点

**特殊模式不附带成人内容或预制成人爬虫，也不会自动下载“特殊版本”。** 它允许你安装自己指定的本地 Python 适配器。仅修改模式或填一个新网址，并不能让程序理解任意网站的页面结构。

### 让 agent 配置特殊模式

先完成普通模式部署，再向 agent 提供你有权抓取的站点、所需页面或 API 文档，并发送：

> 我需要启用特殊模式。请阅读 README 的手动加站步骤和 special_plugin.example.py。我会提供目标站点、允许抓取的页面范围及必要的 API 或页面结构资料。请在 private/provider.py 实现该站点的 collect(url, config) 和 resolve(video, config)，限制允许的域名、翻页数量、请求超时和导入条数，不绕过登录、付费或访问控制，不加入我没有指定的来源。先用少量数据验证，再修改本机 config.json 启用 mode=special。授权仅使用我自己的文件，保存在 .secrets 内，不写入源码或 Git。最后告诉我如何手动添加同站点新栏目或新的站点，以及如何切回普通模式。

### 手动添加步骤

1. **准备适配器。** 在项目目录创建 `private`，将 `special_plugin.example.py` 复制为 `private/provider.py`。模板只定义接口，尚不能抓取；需要你或 agent 按目标站点实现解析逻辑。
2. **实现目录采集 `collect(url, config)`。** 根据输入的目录页、合集页或 API 获取视频信息，并逐条 `yield`。在请求和分页过程中遵守 `config["max_items_per_source"]`，使用网络超时，不要先把全站目录载入内存。
3. **实现播放解析 `resolve(video, config)`。** 根据视频的 `page_url` 或稳定编号，实时解析可访问的 MP4/HLS 地址。带签名的播放地址可能过期，不要把旧地址硬编码在源码中。
4. **配置明确的来源。** 修改本机 `config.json` 中下列字段，保留其他原有字段。示例域名 `media.example` 是占位符，必须换成自己适配器支持的站点：

   ```json
   {
     "mode": "special",
     "special_plugin": "private/provider.py",
     "sources": ["https://media.example/catalog"],
     "max_items_per_source": 3
   }
   ```

5. **小量验证。** 在另一个终端运行 `start-windows.bat crawler` 或 `bash start-ubuntu.sh crawler`。确认导入成功，再重启网页服务并检查标题、封面、源站播放；云缓存只在你已配置自己的存储时测试。验证后可提高单来源条数，范围为 1–200，默认 50。
6. **继续添加来源。** 同一站点的新栏目或新合集，在适配器支持对应路径后追加到 `sources`。新增不同站点，需要先扩展 `private/provider.py` 的域名路由及解析逻辑，再追加链接；不同站点使用不同的 `site` 标识。单份配置最多 20 个来源。
7. **切回普通模式。** 将 `mode` 改回 `ordinary`，将 `sources` 改成 Bilibili/抖音链接或空数组，重启服务。切换模式不会删除已经导入的本机目录；需要两套互不混杂的目录时，请使用两个独立安装目录。

### 适配器返回什么

`collect` 每次产出一个字典，字段约定如下：

| 字段 | 用途 |
| --- | --- |
| `site` | 稳定站点标识，例如 `my_site`；只用字母、数字、下划线或连字符 |
| `code` | 站内稳定且唯一的视频编号；同站点同编号会更新目录 |
| `title` | 视频标题 |
| `page_url` | 对应的视频详情页，供后续重新解析播放地址 |
| `downloadable` | 有可用解析逻辑时设为 `true` |
| `duration`、`date` | 可选；时长秒数或时分秒字符串，日期为 `YYYY-MM-DD` |
| `source_views`、`tags`、`thumb` | 可选；播放量数字、标签字符串数组和封面 URL |

`resolve` 返回字典，例如以下结构（同样仅为占位示例）：

```python
{
    "url": "https://cdn.example/video/index.m3u8",
    "kind": "hls",
    "referer": "https://media.example/"
}
```

单文件 MP4 使用 `kind="mp4"`。若源站提供分离的 H.264 视频与 AAC 音频，则另返回 `audio_url` 和 `remux=True`。推荐浏览器兼容的 H.264/AAC 格式，不承诺任意编码均能直接播放。

适配器需要 Cookie 或其他授权时，由适配器明确读取用户指定的 `.secrets` 文件；特殊模式不会自动替自定义适配器处理登录。`collect` 和 `resolve` 在独立子进程执行，整个解析调用有 120 秒超时；Ubuntu 另有 512 MiB 地址空间上限。缺少实现、权限或有效媒体地址时应明确报错，不能伪造成功结果。

详细部署流程见 [DEPLOYMENT.md](DEPLOYMENT.md)，agent 执行要求见 [AGENT_DEPLOYMENT.md](AGENT_DEPLOYMENT.md)。

## 功能范围

- 视频目录浏览、搜索、标签筛选和热门排序。
- 源站播放与手动缓存，支持缓存队列、进度查看及任务取消。
- 配置用户自己的存储后保存视频；公开版本不得携带作者的云盘账号或授权。

公开版本的默认普通模式以 **Bilibili 和抖音**为支持范围，仅面向用户有权访问、下载和保存的内容。能在浏览器中观看，不当然代表有下载、转载或再分发授权。平台接口、账号权限与内容可用性可能变化，不保证任意链接均可解析或播放。
